# Prototype brief

Use this brief when a design question needs a runnable answer. Read
[`docs/development/prototypes.md`](../../development/prototypes.md) first. The prototype is throwaway; the decision
is the deliverable.

| Field | Value |
| --- | --- |
| Date | YYYY-MM-DD |
| Step or decision | — |
| Owner | Design agent / dev |

```text
Question to answer:
- <one answerable question>

Shape:
- Logic/state model / UI/interaction / other:

Why a runnable answer is needed:
- <what cannot be settled on paper>

Location:
- .tmp/prototypes/<slug> / /home/node/tmp/<slug> / throwaway branch <name>

What to build:
- <minimum harness or variants>
- <state to surface after each action>

How to run it:
- <one command or file to open>

What the owner should judge:
- <cases, variants, or trade-offs>

Stop before:
- adding tests, abstractions, persistence, or polish
- touching main or a step/feature branch
- turning the prototype into the implementation

Record when done:
- answer:
- decision:
- ADR or step-page link:
- prototype kept or deleted:
```
